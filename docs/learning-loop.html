学習ループ

手を動かしただけで終わらせないための仕組み

なぜこれが要るのか
コマンドを打って結果を眺めるだけだと、「そういうものか」で終わる。 先に予測を書くと、外れた瞬間に自分の思い込みが表に出る。そこが学習の起点になる。 予測を書かせるだけの教材は飛ばされるので、このプラットフォームでは 予測を入れるまで解説が出ないようにしてある。

0. 脅威を固定する

各章は、操作より先に脅威ブリーフを置きます。資産、守る性質、攻撃者の能力、成立の前提、 この実験で除外する能力、攻撃成功、観測点を先に固定します。

run-as、Burp、Fridaは攻撃者の名前ではなく道具です。同じ道具でも前提が違えば結論が変わるため、 章末では「安全になった」ではなく、能力Xに対して経路Yを止めたが、経路Zは残るという形で判定します。

4つの段

① 予測する

実行前に「成功する / 失敗する」と、その理由を入力する。ガイドの各手順に欄がある。

② 確かめる

実際に打って結果を入れる。ここで初めて解説が開く。

③ 説明する

章末に、自分の言葉で仕組みを書く。観点は自己採点。

④ 検証する

概念テストと、AI の出力を実験で反証する課題。

① 予測する / ② 確かめる

各章の Standard 層と Deep 層の冒頭に、こういう欄が埋め込んであります。 操作は全部ページの中で完結する。

予測（見本）run-as を外して shared_prefs を読む

adb shell から直接 cat は通るか。

…理由を書いて記録すると、次に「実際の結果」を入れる欄に変わる。

結果を入れると、予測・実測・正解が並び、なぜそうなるのかが開く。 予測を外していた場合は、そこで何を見直せばよいかも出る。

外してよい
的中率は高ければよいものではない。外した手順は 記録 に残り、 「どこで誤解していたか」の記録になる。むしろそこが成果物になる。

③ 説明する

章末に 説明課題 がある。4〜5問に自分の言葉で答え、 そのあと「必要な観点が入っているか」を自己採点する。 抜けている観点には、どの手順に戻ればよいかが表示される。

④ 検証する

概念テストの選択肢には、実際によくある誤解が仕込んであります。 「root を取られたら暗号化は無意味」「HTTPS なら中身は見られない」といったもので、 引っかかった誤解がその場で名指しされる。

オラクル演習は AI が出した診断と修正案を判定する課題。 実在しない API を使った修正、ファイル名を変えただけの「修正」、 正しく見えるが攻撃者の位置を場合分けしていない「問題なし」判定などが混ざっている。 脆弱性を見つける課題ではなく、主張を実験で棄却する課題。

記録

記録のページに、手順ごとの状態（未着手 / 予測済み / 的中 / 外した）、 予測の的中率、外した手順とそのときの理由、概念テストの事前事後の差がまとまる。

記録の置き場所
通常の学習記録はブラウザの中だけに保存され、JSONで持ち出せます。 研究用の集計はこれとは別で、研究参加に明示同意した場合だけ、 自由記述を除く構造化イベントを外部へ送ります。同意しなくても教材は利用できます。
ページは http://localhost:8000/docs/ から開くこと。 file:// で開くと保存できないブラウザがある。起動方法は 環境構築 を参照。

おすすめの順番

  1. 研究参加者は、教材を見る前に研究参加から学習前テストを受ける。教材内の概念テストは練習用で、研究テストとは分ける
  2. 各章を Basic → Standard と進める。Standard では手順ごとに予測 → 確認
  3. 章末で説明課題。書けなければ、その章の Standard に戻る
  4. 全章が終わったら概念テストを事後として受ける。事前との差が出る
  5. 記録で全体を振り返る
