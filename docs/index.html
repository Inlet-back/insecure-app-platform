Android セキュリティ学習プラットフォーム

脆弱性を見つける演習ではなく、脆弱性が成立する条件と防御が効く範囲を実験で確かめる演習

Android の主役は、アプリのバグではなく OS が各アプリを箱に閉じ込めていること です。 この教材は、その箱がどこから破れるかで4章に分けてあり、どの章にも攻撃側と防御側の両方を置いています。 「どうやって漏れるか」で終わらせず、「なぜ普段は漏れないのか」まで見に行きます。

手を動かす前に読むページは1枚だけです。 そこで何を確かめに行くのかとどの立場で確かめるのかを決めてから、エミュレータに移ります。

先にこの3つを落としてください
ソース一式（.zip） 被害者アプリ（.apk） 攻撃者アプリ（.apk）
落としたら 環境構築 を上から順に貼っていけば、実験できる状態になります。 ダウンロードもコマンドで済ませたい場合は、環境構築の手順1 にコマンドがあります。
導入を読む（15分・座学のみ） 環境構築 5分クイックチェック

3つの層

各章は3層に分かれています。Basic だけを通しても、この教材は一周できます。

層時間やること
Basic30分手順どおりに打って結果を見る。攻撃が1回成功して終わり
Standard1〜2時間条件を1つずつ変えて比べ、守られている理由を OS 側で確認する
Deep任意防御の限界を見る。Frida を使う
進み方の目安
はじめて → 全章の Basic だけ。「4種類の漏れ方を体験した」で完結します。
もう少し深く → 全章の Standard まで。「OS がどう守っているか説明できる」に到達します。
とことん → 気になった章の Deep へ。やらなくても学習は完結します。

通しでやる順番

  1. 何もやる前に 概念テスト（全章） を事前として受ける。ほとんど解けなくて構いません
  2. 導入 を読み、環境構築 を済ませる
  3. 各章を Basic → Standard と進める。Standard では手順ごとに、打つ前に予測を書く
  4. 章末の 説明課題。書けなければ、その章の Standard に戻る
  5. 全章を終えたら 攻撃面マップ と オラクル演習
  6. 概念テストを事後として受け直し、記録で全体を振り返る
概念テスト 説明課題 オラクル演習 自分の記録

章

第1章 — プロセス境界

平文で保存された認証情報を取り出し、次に「なぜ他アプリからは読めないのか」を UID と SELinux で確認する。暗号化がどこまで守るのかまで見る。

第2章 — IPC境界

ファイルの権限は変えていないのに、ContentProvider と Intent から 同じデータが出ていく。exported と permission を1段ずつ変えて比べる。

第3章 — ネットワーク境界

端末の外に出た認証情報を捕まえる。HTTPS が読めるかどうかは 暗号の強さではなく信頼ストアの中身で決まることを実験で示す。

第4章 — 実行環境境界

APK から鍵を取り出して復号する。次に Keystore に鍵を移し、 「取り出せない」と「使えない」が別物であることを確かめる。

横断 — 攻撃面マップ

章を終えてから戻る表。資産に、どの立場から届くかを数える。 Basic / Standard / Deep の3枚に分かれていて、層が上がると列が増える。

終章 — この先どこで調べるか

4章を4行に畳み、共通していた1つの問いを取り出す。 MASVS / MASTG と公式ドキュメントの使い分け、教材の外での次の一歩まで。
