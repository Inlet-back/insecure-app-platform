1. 配布物を落として展開する

ソース一式（InsecureAppPlatform-src.zip）と、2つの APK を落とします。 合わせて 12MB ほどです。

mkdir -p "$HOME/ws" &&
iap_unpack=$(mktemp -d "$HOME/ws/iap.XXXXXX") &&
curl -fL https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/InsecureAppPlatform-src.zip -o "$iap_unpack/source.zip" &&
unzip -q "$iap_unpack/source.zip" -d "$iap_unpack" &&
cd "$iap_unpack"/InsecureAppPlatform-*/ &&
curl -fLO https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/app-debug.apk &&
curl -fLO https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/attacker-debug.apk &&
pwd
$ErrorActionPreference = "Stop"
New-Item -ItemType Directory -Path "$HOME\ws" -Force | Out-Null
Set-Location "$HOME\ws"
Invoke-WebRequest https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/InsecureAppPlatform-src.zip -OutFile InsecureAppPlatform-src.zip
Expand-Archive .\InsecureAppPlatform-src.zip -DestinationPath . -Force
$project = Get-ChildItem -Directory -Filter "InsecureAppPlatform-*" |
  Sort-Object Name -Descending | Select-Object -First 1
if (!$project -or !(Test-Path (Join-Path $project.FullName "gradlew.bat"))) {
  throw "ソースの展開先が見つかりません。ZIPのダウンロードと展開を確認してください。"
}
Set-Location $project.FullName
Invoke-WebRequest https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/app-debug.apk -OutFile app-debug.apk
Invoke-WebRequest https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/attacker-debug.apk -OutFile attacker-debug.apk
pwd

ブラウザから落とすなら、この3つをクリックしてください。 保存先はこのあと cd するフォルダに揃えます。

2. JDK と Android SDK を入れる

macOS 標準のターミナル（zsh）を使います。まず Homebrew を使える状態にします。 未導入ならインストーラが実行され、パスワードや Command Line Tools の導入を求められる場合があります。

(
  set -eu
  if ! command -v brew >/dev/null 2>&1 &&
     [ ! -x /opt/homebrew/bin/brew ] && [ ! -x /usr/local/bin/brew ]; then
    iap_installer=$(mktemp)
    curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh -o "$iap_installer"
    /bin/bash "$iap_installer"
    rm "$iap_installer"
  fi
) && {
  if [ -x /opt/homebrew/bin/brew ]; then
    eval "$(/opt/homebrew/bin/brew shellenv)"
  elif [ -x /usr/local/bin/brew ]; then
    eval "$(/usr/local/bin/brew shellenv)"
  fi
  command -v brew
}

JDK と SDK ツールを入れ、設定を専用ファイルへ保存します。 Apple Silicon / Intel は自動判定します。Apple Silicon では Rosetta で起動したターミナルを使わないでください。

(
  set -eu
  brew install --cask temurin@17
  brew install --cask android-commandlinetools
  mkdir -p "$HOME/.config/insecure-app-platform"
  cat > "$HOME/.config/insecure-app-platform/android-env.sh" <<'ENV'
JAVA_HOME=$(/usr/libexec/java_home -v 17) || return 1
export JAVA_HOME
export ANDROID_HOME="$HOME/android-sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/cmdline-tools/latest/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
case "$(uname -m)" in
  arm64) export IAP_ANDROID_ABI=arm64-v8a ;;
  x86_64) export IAP_ANDROID_ABI=x86_64 ;;
  *) echo "未対応の CPU です" >&2; return 1 ;;
esac
ENV
  source "$HOME/.config/insecure-app-platform/android-env.sh"
  # 最初は Homebrew が配置したツールで、指定した SDK フォルダへ導入します。
  iap_sdkmanager="$(brew --prefix)/bin/sdkmanager"
  test -x "$iap_sdkmanager"
  "$JAVA_HOME/bin/java" -version
  "$iap_sdkmanager" --sdk_root="$ANDROID_HOME" --licenses
  "$iap_sdkmanager" --sdk_root="$ANDROID_HOME" \
    "cmdline-tools;latest" "platform-tools" "emulator" \
    "system-images;android-33;google_apis;$IAP_ANDROID_ABI" \
    "platforms;android-35" "build-tools;35.0.0"
) && source "$HOME/.config/insecure-app-platform/android-env.sh" && adb version

赤いエラーやダウンロード失敗が出たら、そのブロックで止めてください。 新しいターミナルでは、次の行で設定を読み戻します。そのあと手順1 の最後に表示されたフォルダへ移動してください。

source "$HOME/.config/insecure-app-platform/android-env.sh"

次に SDK を取得します。Downloads フォルダへの手動保存は不要です。

$ErrorActionPreference = "Stop"
# Google の SDK 配布一覧から Windows 用の安定版を取得します。
[Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12
[xml]$catalog = (Invoke-WebRequest -UseBasicParsing `
  "https://dl.google.com/android/repository/repository2-1.xml").Content
$package = $catalog.SelectSingleNode("//*[local-name()='remotePackage' and @path='cmdline-tools;latest'][*[local-name()='channelRef' and @ref='channel-0']]")
if (!$package) { throw "SDK 配布一覧に安定版が見つかりません。" }
$archive = $package.SelectSingleNode(".//*[local-name()='archive'][*[local-name()='host-os']='windows']/*[local-name()='complete']")
if (!$archive) { throw "Windows 用 SDK が見つかりません。" }
$file = $archive.SelectSingleNode("*[local-name()='url']").InnerText
if ($file -notmatch '^commandlinetools-win-[0-9]+_latest\.zip$') { throw "SDK のファイル名を確認してください。" }
$stage = Join-Path $env:TEMP ("iap-sdk-" + [guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $stage | Out-Null
$zip = Join-Path $stage "sdk.zip"
Invoke-WebRequest -UseBasicParsing "https://dl.google.com/android/repository/$file" -OutFile $zip
$checksum = $archive.SelectSingleNode("*[local-name()='checksum']").InnerText
if ((Get-FileHash $zip -Algorithm SHA1).Hash -ne $checksum.Trim()) {
  throw "SDK のチェックサムが一致しません。手順2をやり直してください。"
}
Expand-Archive -LiteralPath $zip -DestinationPath $stage
$toolsDir = Join-Path $env:ANDROID_HOME "cmdline-tools"
$latest = Join-Path $toolsDir "latest"
New-Item -ItemType Directory -Path $toolsDir -Force | Out-Null
if (Test-Path $latest) {
  # 再実行時は既存のフォルダを残します。
  Move-Item -LiteralPath $latest -Destination (Join-Path $toolsDir ("backup-" + [guid]::NewGuid().ToString()))
}
Move-Item -LiteralPath (Join-Path $stage "cmdline-tools") -Destination $latest
$sdkmanager = Join-Path $latest "bin\sdkmanager.bat"
if (!(Test-Path $sdkmanager)) { throw "sdkmanager.bat がありません。展開結果を確認してください。" }
& $sdkmanager "--sdk_root=$env:ANDROID_HOME" --licenses
if ($LASTEXITCODE -ne 0) { throw "ライセンス確認に失敗しました。" }
& $sdkmanager "--sdk_root=$env:ANDROID_HOME" `
  "platform-tools" "emulator" "system-images;android-33;google_apis;x86_64" `
  "platforms;android-35" "build-tools;35.0.0"
if ($LASTEXITCODE -ne 0) { throw "SDK のインストールに失敗しました。" }
adb version
ライセンスへの同意を聞かれます
--licenses が何回か聞いてきます。目を通して y を返してください。 飛ばすと、次のインストールが黙って止まります。

3. AVD を作って起動する

source "$HOME/.config/insecure-app-platform/android-env.sh" && (
  set -eu
  avdmanager create avd -n ws -d pixel_7 \
    -k "system-images;android-33;google_apis;$IAP_ANDROID_ABI"
  emulator -avd ws > "$HOME/.config/insecure-app-platform/emulator.log" 2>&1 &
  iap_emulator_pid=$!
  # 接続だけでなく Android の起動完了まで、最大5分待ちます。
  iap_booted=0
  for iap_attempt in {1..150}; do
    if [ "$(adb -e shell getprop sys.boot_completed 2>/dev/null | tr -d '\r')" = "1" ]; then
      iap_booted=1
      break
    fi
    if ! kill -0 "$iap_emulator_pid" 2>/dev/null; then break; fi
    sleep 2
  done
  if [ "$iap_booted" != "1" ]; then
    echo "起動を確認できません。android-env.sh と同じフォルダの emulator.log を確認してください。" >&2
    exit 1
  fi
  adb -e shell getprop ro.build.version.sdk
)
avdmanager create avd -n ws -d pixel_7 `
  -k "system-images;android-33;google_apis;x86_64"
if ($LASTEXITCODE -ne 0) { throw "AVD の作成に失敗しました。" }
Start-Process -FilePath "$env:ANDROID_HOME\emulator\emulator.exe" -ArgumentList "-avd","ws"
adb wait-for-device
adb shell getprop ro.build.version.sdk
途中で1回だけ聞かれます
Do you wish to create a custom hardware profile? [no] には、 そのまま Enter を押してください。
Google Play 版のイメージを選ばない
Play ストア入りのイメージは adb root ができません。 第1章手順10以降と第4章 Advancedで必要になります。上のコマンドは google_apis 版を指定しています。

33 と返れば、端末の準備は終わりです。初回の起動は数分かかります。

4. 2つのアプリを入れる

被害者アプリと攻撃者アプリは別々の APKで、別々の UID を持ちます。 これが第1章・第2章の実験の前提になります。

adb install -r app-debug.apk
adb install -r attacker-debug.apk
adb shell pm list packages -U | grep -E "insecureappplatform|attacker"
adb shell pm list packages -U | Select-String "insecureappplatform|attacker"
package:com.example.attacker uid:10247
package:com.example.insecureappplatform uid:10246

UID が違っていれば準備完了です。ここまでで第1章と第2章は最後まで通ります。

中身が壊れていないか確かめる
Releases のページに載せた sha256 と一致することを確かめてください。 
shasum -a 256 app-debug.apk attacker-debug.apk
Get-FileHash app-debug.apk,attacker-debug.apk -Algorithm SHA256
keys/ は消さないこと
2つのアプリは別々の鍵で署名してあります。配布物の keys/ に、 配った APK と同じ鍵が入っています。特別な操作は要りません。
消してしまったときの直し方

次のビルドで別の鍵が自動生成され、配った APK と署名が食い違います。 その状態で入れ直すと INSTALL_FAILED_UPDATE_INCOMPATIBLE で落ちます。 両アプリを消してから入れ直してください。

adb uninstall com.example.insecureappplatform
adb uninstall com.example.attacker

鍵が別々であることは、第2章の signature permission の実験が前提にしています。 入っているのは教材専用の使い捨ての鍵で、本番には使いません。

5. モックサーバ（第3章で使う）

Python が未導入なら、手順2 と同じターミナルで先に実行してください。

brew install python

サーバは起動したままにします。以降の作業は別のターミナルでリポジトリのルートへ移動して進めてください。 新しいターミナルでは手順2 の source も実行します。

python3 tools/mockserver/server.py

起動時に表示される公開鍵ピンは第3章 Standard 手順6 で使います。 待ち受けは 127.0.0.1 のみで、エミュレータからは 10.0.2.2 として見えます。 第3章 手順7 では --expired を付けて起動し直します。

同梱の証明書と秘密鍵は使い捨ての教材用
tools/mockserver/ の CA・サーバ証明書・サーバの秘密鍵は、 秘密鍵ごとリポジトリに入っています。誰でも中身を読める前提の材料なので、 この教材のループバック以外には絶対に使わないでください。 作り直すときは tools/mockserver/make-teaching-certs.sh を実行します。 作り直すとアプリが同梱している CA も差し替わるので、 そのあとアプリの再ビルドと再インストール（./gradlew :app:installDebug）が要ります。 忘れると第3章 手順4 と同じ Trust anchor not found が出ます。 スクリプトが最後にこのことを表示します。

7. Frida（Advancedのみ・任意）

Advancedをやらないなら不要です。端末の ABI に合う frida-server を frida のリリースページから落とします。 Apple Silicon の AVD なら arm64 です。Windows の AVD なら x86_64 です。

pip install frida-tools
frida --version        # ← このバージョンと frida-server を必ず一致させる

adb root
adb push frida-server-<version>-android-<abi> /data/local/tmp/
adb shell chmod 755 /data/local/tmp/frida-server-<version>-android-<abi>
adb shell "nohup /data/local/tmp/frida-server-<version>-android-<abi> >/dev/null 2>&1 &"

frida-ps -Ua | head     # アプリが一覧に出れば準備完了
スクリプトの流し込み方
対象アプリを前面に出した状態で frida -U -F -l <script> を使います （-F は最前面のアプリに接続する指定）。 -f でアプリを起動する形は、起動直後でまだクラスが読み込まれておらず 失敗することがあります。実行はリポジトリのルートから行ってください。

8. Extra: Squeeze を入れる（任意）

Core の4章とは別の、EC アプリを題材にした追加演習です。 Core を終えてからで構いません。やらないなら飛ばしてください。

Core の4つはそのまま残ります
Squeeze は別パッケージです。手順4 で入れた被害者アプリ・攻撃者アプリと、 そこに保存したデータを消さずに追加できます。

入れるところ（手順1〜2）

症状原因と対処
sdkmanager: command not found 手順2 を完了し、新しいターミナルでは source "$HOME/.config/insecure-app-platform/android-env.sh" を実行する手順2 の PATH 設定を確認し、ターミナルを開き直す
brew: command not found 手順2 の最初のブロックで Homebrew を導入し、shellenv でパスを設定する
AVD のイメージが見つからない、CPU が合わない 手順2 と手順3 を同じターミナルで実行する。Apple Silicon は arm64-v8a、Intel は x86_64 を自動選択する
sdkmanager が Java のエラーを出す 手順2 の JDK 設定を実行し、& "$env:JAVA_HOME\bin\java.exe" -version が 17 を示すか確認する
Android Studio のダウンロード画面が出る ブラウザを閉じて、手順2 の PowerShell コマンドで SDK を取得する
Downloads 内の ZIP やパスが見つからない 手順2 は ZIP を一時フォルダに自動取得する。古い手動ダウンロードのコマンドを使わず、手順2 を最初から実行する
新しいターミナルで adb が見つからない Windows Terminal や VS Code を全ウィンドウ終了して開き直す。タブを開き直すだけでは、親アプリの古い環境変数が残ることがある
インストールが黙って止まる ライセンスに同意していない。sdkmanager --licenses を実行する

端末まわり（手順3〜4）

記録はどこに残るか
通常の予測や説明の記録は、ブラウザの中（localStorage）だけに保存されます。 記録のページから JSON で書き出せます。 研究用イベントは、研究参加で明示同意した場合だけ別送信されます。 記録はページの URL ごとに別物になります。
