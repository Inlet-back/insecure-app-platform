手順2 で 2GB ほど落とします
回線が遅いと、ここだけで15分を超えます。展開後に 12GB 以上の空きも要ります。

1. 配布物を落として展開する

ソース一式（InsecureAppPlatform-src.zip）と、2つの APK を落とします。 合わせて 12MB ほどです。

mkdir -p ~/ws && cd ~/ws
curl -LO https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/InsecureAppPlatform-src.zip
unzip -q InsecureAppPlatform-src.zip
cd InsecureAppPlatform-*/
curl -LO https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/app-debug.apk
curl -LO https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/attacker-debug.apk
pwd
mkdir $HOME\ws -Force; cd $HOME\ws
Invoke-WebRequest https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/InsecureAppPlatform-src.zip -OutFile InsecureAppPlatform-src.zip
Expand-Archive .\InsecureAppPlatform-src.zip -DestinationPath . -Force
cd (Get-ChildItem -Directory InsecureAppPlatform-*)[0]
Invoke-WebRequest https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/app-debug.apk -OutFile app-debug.apk
Invoke-WebRequest https://github.com/Inlet-back/insecure-app-platform/releases/latest/download/attacker-debug.apk -OutFile attacker-debug.apk
pwd

ブラウザから落とすなら、この3つをクリックしてください。 保存先はこのあと cd するフォルダに揃えます。

ソース一式（.zip） 被害者アプリ（.apk） 攻撃者アプリ（.apk）

最後に出たパスがリポジトリのルートです。この先のコマンドはすべてここで実行します。

2. JDK と Android SDK を入れる

brew install --cask temurin@17
brew install --cask android-commandlinetools
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export ANDROID_HOME=$HOME/android-sdk
export PATH=$ANDROID_HOME/cmdline-tools/latest/bin:$PATH:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator

sdkmanager --sdk_root="$ANDROID_HOME" --licenses
sdkmanager --sdk_root="$ANDROID_HOME" \
  "cmdline-tools;latest" "platform-tools" "emulator" "system-images;android-33;google_apis;arm64-v8a"

Intel の Mac なら、最後の arm64-v8a を x86_64 に読み替えてください。

winget install --id EclipseAdoptium.Temurin.17.JDK

コマンドラインツールは winget に無いので、 developer.android.com から commandlinetools-win-<番号>_latest.zip を落とします。 展開先のフォルダ名を latest にするところが要点です。

$env:ANDROID_HOME = "$HOME\android-sdk"
mkdir "$env:ANDROID_HOME\cmdline-tools" -Force
Expand-Archive "$HOME\Downloads\commandlinetools-win-*_latest.zip" `
  -DestinationPath "$env:ANDROID_HOME\cmdline-tools"
Rename-Item "$env:ANDROID_HOME\cmdline-tools\cmdline-tools" "latest"

$env:Path += ";$env:ANDROID_HOME\cmdline-tools\latest\bin"
$env:Path += ";$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\emulator"

sdkmanager --sdk_root="$env:ANDROID_HOME" --licenses
sdkmanager --sdk_root="$env:ANDROID_HOME" `
  "platform-tools" "emulator" "system-images;android-33;google_apis;x86_64"
ライセンスへの同意を聞かれます
--licenses が何回か聞いてきます。目を通して y を返してください。 飛ばすと、次のインストールが黙って止まります。

3. AVD を作って起動する

avdmanager create avd -n ws -d pixel_7 \
  -k "system-images;android-33;google_apis;arm64-v8a"
emulator -avd ws &
adb wait-for-device
adb shell getprop ro.build.version.sdk
avdmanager create avd -n ws -d pixel_7 `
  -k "system-images;android-33;google_apis;x86_64"
Start-Process emulator -ArgumentList "-avd","ws"
adb wait-for-device
adb shell getprop ro.build.version.sdk
途中で1回だけ聞かれます
Do you wish to create a custom hardware profile? [no] には、 そのまま Enter を押してください。
Google Play 版のイメージを選ばない
Play ストア入りのイメージは adb root ができません。 第1章手順10以降と第4章 Advancedで必要になります。上のコマンドは google_apis 版を指定しています。

33 と返れば、端末の準備は終わりです。初回の起動は数分かかります。

4. 2つのアプリを入れる

被害者アプリと攻撃者アプリは別々の APKで、別々の UID を持ちます。 これが第1章・第2章の実験の前提になります。

adb install -r app-debug.apk
adb install -r attacker-debug.apk
adb shell pm list packages -U | grep -E "insecureappplatform|attacker"
adb shell pm list packages -U | Select-String "insecureappplatform|attacker"
package:com.example.attacker uid:10247
package:com.example.insecureappplatform uid:10246

UID が違っていれば準備完了です。ここまでで第1章と第2章は最後まで通ります。

中身が壊れていないか確かめる
Releases のページに載せた sha256 と一致することを確かめてください。 
shasum -a 256 app-debug.apk attacker-debug.apk
Get-FileHash app-debug.apk,attacker-debug.apk -Algorithm SHA256
keys/ は消さないこと
2つのアプリは別々の鍵で署名してあります。配布物の keys/ に、 配った APK と同じ鍵が入っています。特別な操作は要りません。
消してしまったときの直し方

次のビルドで別の鍵が自動生成され、配った APK と署名が食い違います。 その状態で入れ直すと INSTALL_FAILED_UPDATE_INCOMPATIBLE で落ちます。 両アプリを消してから入れ直してください。

adb uninstall com.example.insecureappplatform
adb uninstall com.example.attacker

鍵が別々であることは、第2章の signature permission の実験が前提にしています。 入っているのは教材専用の使い捨ての鍵で、本番には使いません。

5. モックサーバ（第3章で使う）

python3 tools/mockserver/server.py

起動時に表示される公開鍵ピンは第3章 Standard 手順6 で使います。 待ち受けは 127.0.0.1 のみで、エミュレータからは 10.0.2.2 として見えます。 第3章 手順7 では --expired を付けて起動し直します。

同梱の証明書と秘密鍵は使い捨ての教材用
tools/mockserver/ の CA・サーバ証明書・サーバの秘密鍵は、 秘密鍵ごとリポジトリに入っています。誰でも中身を読める前提の材料なので、 この教材のループバック以外には絶対に使わないでください。 作り直すときは tools/mockserver/make-teaching-certs.sh を実行します。 作り直すとアプリが同梱している CA も差し替わるので、 そのあとアプリの再ビルドと再インストール（./gradlew :app:installDebug）が要ります。 忘れると第3章 手順4 と同じ Trust anchor not found が出ます。 スクリプトが最後にこのことを表示します。

6. ソースからビルドする（第3章で使う）

第3章の差分実験では network_security_config.xml を書き換えて入れ直します。 そこで初めてビルドが要ります。第1章・第2章だけなら手順4 のままで構いません。

export JAVA_HOME=$(/usr/libexec/java_home -v 17)
./gradlew :app:installDebug
$env:JAVA_HOME = (Get-Item "C:\Program Files\Eclipse Adoptium\jdk-17*").FullName
.\gradlew.bat :app:installDebug
JDK が新しすぎると一行だけのエラーで落ちます
* What went wrong:
    25.0.3
Gradle 8.11 / AGP 8.9 が JDK 25 に未対応です。上のように JDK 17 を指定してください。
ANDROID_HOME が今のシェルから消えていると落ちます
SDK location not found. Define a valid SDK location with an ANDROID_HOME
environment variable or by setting the sdk.dir path in your project's
local properties file at '.../local.properties'
手順2 の環境変数の行をもう一度実行するか、local.properties に書いてください。 
sdk.dir=/Users/<あなた>/android-sdk
sdk.dir=C\:\\Users\\<あなた>\\android-sdk

7. Frida（Advancedのみ・任意）

Advancedをやらないなら不要です。端末の ABI に合う frida-server を frida のリリースページから落とします。 Apple Silicon の AVD なら arm64 です。Windows の AVD なら x86_64 です。

pip install frida-tools
frida --version        # ← このバージョンと frida-server を必ず一致させる

adb root
adb push frida-server-<version>-android-<abi> /data/local/tmp/
adb shell chmod 755 /data/local/tmp/frida-server-<version>-android-<abi>
adb shell "nohup /data/local/tmp/frida-server-<version>-android-<abi> >/dev/null 2>&1 &"

frida-ps -Ua | head     # アプリが一覧に出れば準備完了
スクリプトの流し込み方
対象アプリを前面に出した状態で frida -U -F -l <script> を使います （-F は最前面のアプリに接続する指定）。 -f でアプリを起動する形は、起動直後でまだクラスが読み込まれておらず 失敗することがあります。実行はリポジトリのルートから行ってください。

8. Extra: Squeeze を入れる（任意）

Core の4章とは別の、EC アプリを題材にした追加演習です。 Core を終えてからで構いません。やらないなら飛ばしてください。

Core の4つはそのまま残ります
Squeeze は別パッケージです。手順4 で入れた被害者アプリ・攻撃者アプリと、 そこに保存したデータを消さずに追加できます。

Extra の2つは APK を配っていません。手順1 で展開したソース一式の中に squeeze/ が入っているので、そこからビルドします。 ビルドと同時にエミュレータへ入るので adb install は要りません。

cd ~/ws/InsecureAppPlatform-*/
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
./gradlew :squeeze:installDebug :squeeze-attacker:installDebug
cd (Get-ChildItem -Directory $HOME\ws\InsecureAppPlatform-*)[0]
$env:JAVA_HOME = (Get-Item "C:\Program Files\Eclipse Adoptium\jdk-17*").FullName
.\gradlew.bat :squeeze:installDebug :squeeze-attacker:installDebug

4つのアプリが別々に並べば入っています。

adb shell pm list packages | grep -E "insecureappplatform|attacker"
adb shell pm list packages | Select-String "insecureappplatform|attacker"
package:com.example.insecureappplatform
package:com.example.attacker
package:com.example.insecureappplatform.squeeze
package:com.example.squeeze.attacker
署名は Core と同じ鍵です
Squeeze は被害者アプリと同じ鍵、Squeeze Lab は攻撃者アプリと同じ鍵で署名されます。 第2章で見た signature permission の実験が、Extra 側でもそのまま成立します。

Extra のデータだけを消したいときはこれを実行します。Core の記録とアプリデータには触れません。

./tools/squeeze/reset-extra.sh
adb shell pm clear com.example.insecureappplatform.squeeze
adb shell pm clear com.example.squeeze.attacker

よくある詰まり

入れるところ（手順1〜2）

症状原因と対処
sdkmanager: command not found PATH の行が効いていない。ターミナルを開き直したら入れ直す
sdkmanager が Java のエラーを出す 展開したフォルダ名が latest になっていない。 cmdline-tools\latest\bin\ の形にする
インストールが黙って止まる ライセンスに同意していない。sdkmanager --licenses を実行する

端末まわり（手順3〜4）

症状原因と対処
エミュレータが起動しない 「Windows の機能」から Windows ハイパーバイザー プラットフォームを有効にして再起動するディスクの空きを確かめる。初回は数分かかるので待つ
adb: no devices/emulators found AVD が起動していない。emulator -avd ws のあと adb wait-for-device
INSTALL_FAILED_OLDER_SDK 端末の API が minSdk 24 未満。手順3 で API 33 を指定し直す
INSTALL_FAILED_UPDATE_INCOMPATIBLE 入っている APK と署名が違う。両アプリを adb uninstall してから入れ直す
adbd cannot run as root Google Play 版イメージ。google_apis 版で AVD を作り直す

ビルドと、章の中で（手順6 以降）

症状原因と対処
What went wrong: 25.0.3 JDK が新しすぎる。JDK 17 を指定する
SDK location not found ANDROID_HOME が消えている。手順2 の行を実行し直す
run-as: package not debuggable release ビルドを入れている。配られた APK か installDebug を使う
攻撃者アプリで cursor が null 被害者アプリが未インストール、または <queries> がない
第2章の P4 が成功してしまう 2つの APK が同じ鍵で署名されている。tools/verify/verify-signatures.sh で確認する
第4章で認証つきの鍵を作れない AVD に画面ロックも指紋も登録されていない。設定から登録する
第4章の復号が AEADBadTagException 鍵を作り直したのに古い暗号文を使っている。その鍵で暗号化し直す
記録はどこに残るか
通常の予測や説明の記録は、ブラウザの中（localStorage）だけに保存されます。 記録のページから JSON で書き出せます。 研究用イベントは、研究参加で明示同意した場合だけ別送信されます。 記録はページの URL ごとに別物になります。
