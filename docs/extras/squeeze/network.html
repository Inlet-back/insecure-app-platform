Extra 3 — ネットワーク境界

同じ商品、会員情報、注文操作のまま、通信経路の守りだけを変える

MASVS-NETWORK-1HTTPHTTPSPinning
この演習のゴール
暗号化、証明書の信頼、公開鍵ピンニングがそれぞれ何を確認しているかを分けます。

手順1モックサーバを起動する

python3 tools/mockserver/server.py

外部サービスには接続せず、ホストのループバックだけで待ち受けます。

手順2共通の注文操作を確認する

「ホーム」タブで商品の「追加」を押し、「カート」タブの「購入手続きへ」へ進みます。会員情報が未登録だとボタンが「会員情報を登録する」になるので、先に登録してから「注文を確定する」を押します。成功するとカートが空になるため、比較のたびに商品を追加し直してください。

実行前に予測
HTTP、通常のHTTPS、証明書ピンニングで、経路上の観測者に見えるものと接続の成否がどう変わるか予想します。

手順3通信モードを1つずつ切り替える

./tools/squeeze/set-network-mode.sh http
./tools/squeeze/set-network-mode.sh https
./tools/squeeze/set-network-mode.sh pinned

各コマンドのあとにSqueezeを開き、同じ注文操作を行います。教材用モードは通常画面には表示されません。

比較の要点
HTTPSは端末が通信相手の証明書を信頼できるか検証します。ピンニングは通常のTLS検証を置き換えず、 その後に特定の公開鍵を追加確認します。このExtraの初期ピンは比較用に不一致です。
